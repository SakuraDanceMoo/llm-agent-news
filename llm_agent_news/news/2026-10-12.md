## 1. ThinkingBox：一次成功不等于可靠

**发布时间**：2026-10-03  
**来源**：[Hugging Face 文章](https://huggingface.co/blog/microsoft/thinkingbox)｜[arXiv:2608.19741](https://arxiv.org/abs/2608.19741)｜Zotero `6DE2HBUU`

### 问题是什么

很多 Agent 评测把有效工具调用或看似合理的回复当作完成，但真实业务还要求数据库达到正确终态、产生正确副作用，并且多次运行都可靠。单次成功率会掩盖重复执行时的失败。

### 方法是什么

ThinkingBox 提供隔离的 MCP 工具会话、完整执行轨迹和终端后端状态评测。ThinkingBox-bench 覆盖 507 个有状态业务工作流，并用可执行检查器验证正确、缺失或多余的状态变化。

### 启发是什么

**推断**：Agent 实验应同时报告最终状态断言、重复运行成功率和副作用审计，不能只报告 pass@1 或工具调用正确率。

## 2. AutoSynthData：用失败驱动企业 Agent 训练数据

**发布时间**：2026-10-02  
**来源**：[Hugging Face 文章](https://huggingface.co/blog/ServiceNow-AI/autosynthdata)｜[arXiv:2603.13594](https://arxiv.org/abs/2603.13594)｜Zotero `77AKA26X`

### 问题是什么

企业 Agent 面对特定工具、数据库状态、权限约束和长程规划时会出现能力缺口；单个失败案例不足以直接形成大规模、可训练且可验证的数据集。

### 方法是什么

AutoSynthData 使用目标模型的失败和教师模型的成功生成训练任务，再通过环境可执行性、样本级验证和批次级审查筛选数据。EnterpriseOps-Gym 将企业场景、工具、数据库表和任务验证器组合成评测环境。

### 启发是什么

**推断**：企业 Agent 的数据闭环应采用“能力缺口→任务生成→执行验证→课程更新”，并保留失败轨迹作为训练依据，而不是只扩充自然语言指令数量。

## 3. ProvenanceGuard：MCP 需要来源级事实性校验

**发布时间**：2026-09-29  
**来源**：[Hugging Face 文章](https://huggingface.co/blog/MultiverseComputingCAI/getting-the-source-right-not-just-the-fact-source)｜[arXiv:2606.18037](https://arxiv.org/abs/2606.18037)｜Zotero `RJURFLVJ`

### 问题是什么

MCP Agent 可能从多个搜索、API、数据库或临床记录工具获取证据。一个 claim 即使在混合证据池中有支持，也可能被错误归因给另一个来源，造成来源级事实性错误。

### 方法是什么

ProvenanceGuard 保留稳定的 tool ID 和 source ID，把答案拆成原子 claim，逐条路由到来源特定证据，检查支持关系和答案声称的来源，并输出 allow/block 结果；被阻断的答案可修复后再次验证。

### 启发是什么

**推断**：MCP Agent 的评测应增加 claim-to-source 准确率，把“有证据支持”和“归因于正确来源”作为两个独立指标。
