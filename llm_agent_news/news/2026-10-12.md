## 1. ThinkingBox：一次成功不等于可靠

**发布时间**：2026-10-03  
**事实｜一手来源**：Microsoft/Hugging Face 介绍 ThinkingBox，将 agent 的终端数据库状态和副作用作为验收对象。关联论文在 507 个有状态业务工作流上进行重复试验，强调单次成功率与多次重复成功率之间的差距。

**推断**：工具调用格式正确或回复听起来合理，都不能替代最终状态断言和重复性检验。

**建议**：在 agent 评测中加入最终状态检查、重复运行和副作用审计。

来源：[Hugging Face 文章](https://huggingface.co/blog/microsoft/thinkingbox)；[arXiv:2608.19741](https://arxiv.org/abs/2608.19741)；Zotero 条目 `6DE2HBUU`。

## 2. AutoSynthData：用失败驱动企业 Agent 训练数据

**发布时间**：2026-10-02  
**事实｜一手来源**：ServiceNow CoreAI 介绍 AutoSynthData：根据目标模型失败与教师模型成功生成任务，再通过环境可执行性和验证器筛选样本。关联 EnterpriseOps-Gym 论文覆盖企业工具、数据库状态和长程规划。

**推断**：企业 agent 的训练数据应围绕“能力缺口—任务生成—可执行验证—再训练”构造。

**建议**：优先建立失败轨迹到验证任务的训练闭环。

来源：[Hugging Face 文章](https://huggingface.co/blog/ServiceNow-AI/autosynthdata)；[arXiv:2603.13594](https://arxiv.org/abs/2603.13594)；Zotero 条目 `77AKA26X`。

## 3. ProvenanceGuard：MCP 需要来源级事实性校验

**发布时间**：2026-09-29  
**事实｜一手来源**：Multiverse Computing 介绍 ProvenanceGuard，检查答案中的 claim 是否由其声称的 MCP 来源支持，而不是仅仅在混合证据池中存在。系统保留 source ID，支持阻断或修复答案。

**推断**：MCP agent 的可信度应增加 claim-to-source 维度，不能只报告 pooled-evidence faithfulness。

**建议**：在 trace 中保留 tool ID/source ID，并单独评估来源归因。

来源：[Hugging Face 文章](https://huggingface.co/blog/MultiverseComputingCAI/getting-the-source-right-not-just-the-fact-source)；[arXiv:2606.18037](https://arxiv.org/abs/2606.18037)；Zotero 条目 `RJURFLVJ`。
