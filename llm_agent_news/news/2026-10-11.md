## 1. ThinkingBox：一次成功不等于可靠

**事实｜一手来源**：Microsoft/Hugging Face 介绍 ThinkingBox，将 agent 的终端数据库状态和副作用作为验收对象。文章关联的论文在 507 个有状态业务工作流上进行重复试验，强调 pass@1 与多次重复成功率之间的落差。

**启发｜推断**：评测 agent 时，工具调用格式正确或回复听起来合理，都不能替代最终状态断言和重复性检验。

论文：[*One Success Isn't Reliability*](https://arxiv.org/abs/2608.19741)；Zotero：`6DE2HBUU`，PDF 附件 `W7VVDILG`。

## 2. AutoSynthData：用失败驱动企业 agent 训练数据

**事实｜一手来源**：ServiceNow CoreAI 介绍 AutoSynthData：根据目标模型失败与教师模型成功生成任务，再通过环境可执行性和验证器筛选样本。关联 EnterpriseOps-Gym 论文覆盖企业工具、数据库状态和长程规划。

**启发｜推断**：企业 agent 的数据闭环应围绕“能力缺口—任务生成—可执行验证—再训练”构造。

论文：[*EnterpriseOps-Gym*](https://arxiv.org/abs/2603.13594)；Zotero：`77AKA26X`，PDF 附件 `YYF8YDYA`。

## 3. ProvenanceGuard：MCP 需要来源级事实性校验

**事实｜一手来源**：Multiverse Computing 介绍 ProvenanceGuard，指出“事实在证据池中存在”不代表“答案把事实归因给了正确的 MCP 来源”。系统保留 source ID，逐条检查 claim 支持和来源归因，并可阻断或修复答案。

**启发｜推断**：MCP agent 的可信度应增加 claim-to-source 维度，不能只报告 pooled-evidence faithfulness。

论文：[*ProvenanceGuard*](https://arxiv.org/abs/2606.18037)；Zotero：`RJURFLVJ`，PDF 附件 `A39EPZS5`。
